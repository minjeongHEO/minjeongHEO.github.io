### ✒ 일반 함수를 이벤트 핸들러로 전달하여 콜백 함수를 실행할 때의 this

`class SubmitHandler` 의 메서드에서  
addEventListener로 일반 함수를 이벤트 핸들러로 전달하여 콜백 함수를 실행하려고 했다.

```js
export default class SubmitHandler {
  constructor(formId, textId, classNames) {
    (... 생략)
  }

  (... 생략)

 addEventHandler() {
    document.getElementById(this.formId).addEventListener('submit', this.handleFormSubmit);
  }

 handleFormSubmit(e) {
    e.preventDefault();
    const parseCode = this.createParseCode(); // 콜백 함수를 호출하며 usercode를 매개변수로 전달
    parseCode.body.forEach((obj) => this.extractCallbackCode(obj, this.userCode));
    new EventLoopHandler(this.callBacks, this.classNames);
 };
```

// 이벤트 핸들러 내부의 this는 해당 이벤트 리스너가 부착된 DOM 요소를 가리키게 된다.

💥 <b>이 때 `this.createParseCode()`를 함수로 인식을 못하는 에러가 발생했다.</b>

<i>this.parseCode is not a function at HTMLFormElement.handleFormSubmit</i>

`this`가 예상과 다른 컨텍스트(여기서는 HTMLFormElement)를 가리키고 있기 때문에 발생했다.

JavaScript에서 this의 값은 함수가 호출되는 방식에 따라 달라지며,  
특히 이벤트 핸들러와 같이 콜백 함수에서 this의 값이 자주 예상치 않게 변할 수 있다.

🔽

```js
handleFormSubmit = (e) => {
  e.preventDefault();
  const parseCode = this.createParseCode(); // 콜백 함수를 호출하며 usercode를 매개변수로 전달
  parseCode.body.forEach((obj) => this.extractCallbackCode(obj, this.userCode));
  new EventLoopHandler(this.callBacks, this.classNames);
};
```

💡 <b>해결 방법: 화살표 함수 사용</b>

화살표 함수는 자신을 포함하고 있는 외부 스코프에서 this 값을 가져온다.

따라서, addEventListener의 콜백으로 화살표 함수를 사용하면,  
그 화살표 함수 내부의 this는 addEventListener를 호출한 스코프의 this,  
즉 SubmitHandler 인스턴스를 정확히 가리키게 된다.

### ✒ scope와 this

- <b>스코프</b>는 변수가 어디서 접근 가능한지를 결정하며, 이는 <b>코드가 작성되는 시점(선언될 때)에 결정</b>된다. 반면에,{' '}
- <b>this</b> 키워드는 <b>함수가 실행될 때 결정</b>되는데, 이는 함수가 어떻게 호출되었는지에 따라 달라진다.{' '}

  일반 함수에서 this는 기본적으로 전역 객체(브라우저에서는 window, Node.js에서는 global)를 가리키거나,  
  함수가 어떤 객체의 메소드로 호출될 경우 그 객체를 가리킨다.

  ❗ 하지만, 화살표 함수(arrow function)에서는 this가 조금 다르게 동작한다.

  화살표 함수는 자신을 둘러싼 외부 스코프의 this 값을 "캡처"하여 사용한다.  
  화살표 함수가 선언될 때의 this 값이 화살표 함수 내부에서 사용되는 this의 값으로 고정된다는 의미이다.

  따라서 <b>화살표 함수는 실행될 때의 컨텍스트에 영향을 받지 않는다.<b>

요약하자면, 스코프는 코드가 작성될 때 결정되며 변수의 접근성을 관리하는 반면,  
this는 함수 호출 방식에 따라 결정되지만, 화살표 함수에서는 선언될 때의 this가 화살표 함수 내부에서 사용되는 this로 고정된다.

### ✒ 속성의 값이 있는지 확인할 때

💥 if (parseNode[key])와 같은 조건문으로 값이 있는지 확인하려고 했다.

그러나 이와 같은 조건문은 속성의 값이 "truthy"인지 여부를 검사하므로,  
속성의 존재 여부와는 관계없이 속성의 값에 따라 조건문이 실행이 되므로 의도와는 다르게 실행이 됐다.  
(따라서, 해당 속성이 "falsy" 값을 가지고 있더라도, 속성이 객체에 직접 정의되어 있다면 true를 반환)

💡 [hasOwnProperty](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/hasOwnProperty)  
: 속성의 값과 관계없이, 속성의 존재 자체만을 확인한다.

- 객체가 자신의 속성으로 지정된 속성을 갖고 있는지 여부를 반환 => return `true`
- 그렇지 않으면 => return `false`

이 방법은 속성이 존재하지 않는 것과 속성의 값이 "falsy"인 것  
(예: false, 0, "", null, undefined, NaN) 사이의 차이를 명확하게 구분한다.

💡💡 `Object.prototype.hasOwnProperty.call()`

앗 근데 hasOwnProperty 를 쓰면 안되는 이유가 있다고...???  
[참고 블로그](https://velog.io/@jay/be-carefule-use-hasownproperty)

`Object.prototype.hasOwnProperty.call()`을 사용하는 이유는,

JavaScript에서 객체의 메서드나 속성은 오버라이드(덮어쓰기)될 수 있다.  
(오버라이드는 객체에 이미 존재하는 메서드나 속성을 새로운 값으로 재정의할 때 발생)

예를 들어, 모든 JavaScript 객체는 Object.prototype으로부터 메서드를 상속받는다.  
이에 포함된 hasOwnProperty 메서드는 위에서 설명한 것 처럼,  
객체가 특정 속성을 자신의 직접적인 속성으로 갖고 있는지 확인하는 데 사용되는데,

개발자가 특정 객체에서 hasOwnProperty를 다른 함수로 오버라이드하는 경우가 생길 수가 있다.

```js
const obj = {
  hasOwnProperty: function (prop) {
    console.log(`내가 만든 hasOwnProperty 메서드: ${prop}`);
    // 원래의 Object.prototype.hasOwnProperty를 호출하고 싶다면 여기서 호출해야 함
  },
};

// 이제 obj.hasOwnProperty()를 호출하면, 오버라이드한 함수가 실행.
obj.hasOwnProperty('test'); // "내가 만든 hasOwnProperty 메서드: test" 를 출력
```

<u>정리하자면!</u>
오버라이드된 hasOwnProperty 메서드 대신 Object.prototype에 있는 원본 hasOwnProperty 메서드를 호출하기 위해서이다.{' '}

오버라이드되지 않았다면, 직접 obj.hasOwnProperty('prop')을 호출해도 전혀 문제가 없다.  
하지만 JavaScript에서는 객체를 다루면서 어떤 객체가 Object.prototype의 hasOwnProperty 메서드를 오버라이드했는지 미리 알 수 없는 경우가 많고,  
특히 외부 라이브러리나 다른 개발자가 작성한 객체를 다룰 때는 더욱 그렇다.

이러한 불확실성 때문에, 안전하게 `hasOwnProperty`를 사용하고 싶을 때는 `Object.prototype.hasOwnProperty.call(obj, 'prop')` 방식을 사용해야한다.

### ✒ call과 bind

- call 메서드
  함수를 즉시 호출하면서 <b>첫 번째 인자로 주어진 값을 this로 바인딩</b>하고, <b>이후의 인자들은 호출할 함수의 매개변수로 전달</b>된다.  
  call을 사용하면, <b>함수를 즉시 실행하면서 명시적으로 this 컨텍스트를 설정</b>할 수 있다.

  ```js
  function greet() {
    console.log(`Hello, I am ${this.name}!`);
  }

  const person = { name: 'Woody' };
  greet.call(person); // "Hello, I am Woody!" 출력
  ```

- bind 메서드  
   함수의 <b>this 값을 영구히 바꿀 수 있는 새로운 함수를 반환</b>한다.  
   bind를 사용하면, 함수를 바로 호출하지 않고 <b>this 바인딩을 변경한 새로운 함수를 생성</b>할 수 있다.
  이렇게 반환된 함수는 나중에 호출될 수 있다.

  ```js
  function greet() {
    console.log(`Hello, I am ${this.name}!`);
  }

  const person = { name: 'Woody' };
  const boundGreet = greet.bind(person);
  boundGreet(); // "Hello, I am Woody!" 출력
  ```

### ✒ 객체의 key를 기준으로 반복(iterate)하는 방법

JavaScript에서 객체의 키를 기준으로 반복(iterate)하는 방법은 여러 가지가 있다.

JavaScript에서 객체의 키나 값에 접근하는 방법은 여러 가지가 있으며, 각각의 방법은 다른 목적이나 사용 사례에 적합합니다.  
여기에서는 `Object.keys()`를 포함한 몇 가지 방법과 각 방법의 특징을 설명하겠습니다.

<br>

### 1. `Object.keys()`

`Object.keys()` 메서드는 객체의 모든 열거 가능한(enumerable) 속성의 이름을 <b>문자열 배열로 반환함</b<>  
이 배열을 사용하여 객체의 각 키에 대해 반복 작업을 수행할 수 있다.

```javascript
Object.keys(parseNode).forEach((key) => {
  // key를 사용한 작업
});
```

**👍장점**: 간단하고 명확하며, 객체의 모든 열거 가능한 키를 쉽게 얻을 수 있다.  
**👎단점**: 키만 반환하므로, 값에 접근하려면 별도로 객체에서 키를 사용해야 한다.

### 2. `Object.values()`

`Object.values()` 메서드는 객체의 모든 열거 가능한 속성의 값들을 <b>배열로 반환함</b>  
이 방법은 키 대신 값에 집중해야 할 때 유용하다.

```javascript
Object.values(parseNode).forEach((value) => {
  // value를 사용한 작업
});
```

**👍장점**: 값에 직접 접근할 수 있어 값 기반의 작업에 유용하다.  
**👎단점**: 해당 값의 키에 대한 정보는 제공하지 않는다.

### 3. `Object.entries()`

`Object.entries()` 메서드는 객체의 모든 열거 가능한 속성의 <b>[키, 값] 쌍을 배열로 반환함</b>  
이 배열을 사용하여 객체의 각 속성에 대해 키와 값 모두에 접근할 수 있다.

```javascript
Object.entries(parseNode).forEach(([key, value]) => {
  // key와 value를 사용한 작업
});
```

**👍장점**: 키와 값 모두에 동시에 접근할 수 있어 매우 유용하다.  
**👎단점**: `Object.keys()`나 `Object.values()`에 비해 약간 더 복잡할 수 있다.

### 4. `for...in` 루프

`for...in` 루프는 객체의 모든 열거 가능한 속성을 <b>순회함</b>  
이 방법을 사용하면 객체의 키에 직접 접근할 수 있다.

```javascript
for (let key in parseNode) {
  if (parseNode.hasOwnProperty(key)) {
    // 객체 자신의 속성인지 확인
    // key를 사용한 작업
  }
}
```

**👍장점**: 객체의 키에 직접 접근할 수 있으며, 별도의 함수 호출 없이 사용할 수 있다.  
**👎단점**: 객체의 프로토타입 체인을 통해 상속된 속성도 순회할 수 있으므로,  
 보통 `hasOwnProperty`를 사용하여 객체 자신의 속성인지 확인하는 추가 작업이 필요하다.

### ✒ 고차함수안에서 await

```js
async EventLoopControl() {
  this.callBacks.forEach(async (callBack, idx) => {
    await this.runEvent(callback, idx);
  });
}
```

🔽

```js
async EventLoopControl() {
  for (const [idx, callback] of this.callBacks.entries()) {
    await this.runEvent(callback, idx);
  }
}
```

고차 함수(예: forEach, map, filter 등) 내에서 async/await를 사용하는 것이 "안 되는" 것은 아니지만,  
이렇게 사용했을 때 종종 기대와 다른 결과를 얻게 되는 주된 이유는

고차 함수를 사용할 때 내부에 async 함수를 전달하면, 이 함수들은 각각 별도의 비동기 작업을 시작하는데  
고차 함수 자체는 이러한 비동기 작업들이 언제 완료될지를 기다리지 않고, 즉시 다음 코드로 진행한다.

이는 <b>고차 함수가 비동기 함수들이 반환하는 프로미스를 자동으로 처리하지 않기 때문</b>이다.
